O QUE É ESTE MATERIAL?

Não é um material didático comum. É um MANIFESTO. É uma JORNADA ÉPICA de 3 anos (do 1º ao 3º ano do Ensino Médio) que transforma adolescentes em ARQUITETOS DO FUTURO DIGITAL.

A ESTRUTURA DO CAOS (ORGANIZADO)

📚 O Material está dividido em 4 BIMESTRES por ano:

Ano Bimestres Arquivos Conteúdo Central
1º Ano 4 bimestres ~12 arquivos Fundamentos: HTML, CSS, JS + Cultura Digital
2º Ano 4 bimestres ~12 arquivos Aprofundamento + Projetos Integradores
3º Ano 4 bimestres ~12 arquivos Projetos Completos + Protagonismo

O PROPÓSITO DO MATERIAL

Este material foi criado para transformar alunos em criadores digitais críticos. Não é sobre "aprender a programar" é sobre ENTENDER O SISTEMA, QUESTIONAR O SISTEMA E CONSTRUIR ALTERNATIVAS.

Os Pilares Filosóficos (O que move o material):

  1. Tecnologia não é neutra – algoritmos têm vieses, dados são explorados, atenção é mercadoria.
  2. Você não é o cliente, é o produto – capitalismo de vigilância explicado em cada detalhe.
  3. A revolução será codificada – o conhecimento técnico é poder, e poder se usa.
  4. Feito é melhor que perfeito – MVP, iteração, aprendizado contínuo.
  5. Acessibilidade não é opção, é direito – inclusão em cada linha de código.

O QUE CADA AULA CONTÉM (O PACOTE COMPLETO)

Cada plano de aula (são mais de 40 semanas!) vem com:

  • 📋 1. CARTA DE ABERTURA – Leitura dramática com trilha sonora sugerida. Óculos escuros e jaqueta de couro são obrigatórios. Linguagem que prende: "Senta que lá vem história".
  • 🎯 2. OBJETIVOS OPERACIONAIS – O que o aluno vai aprender. Bônus: a cereja do bolo (o que vai além).
  • 📚 3. CONTEÚDO PROGRAMÁTICO – Tópicos organizados didaticamente. Conexões com a vida real.
  • 🧩 4. PILARES DO PENSAMENTO COMPUTACIONAL – Abstração, Decomposição, Reconhecimento de Padrões, Algoritmos. Aplicação prática em cada aula.
  • 📜 5. HABILIDADES BNCC E RCP-PR – EM13MAT101, EM13LP01, EM13CO23, etc. Alinhamento com o currículo oficial do Paraná.
  • 💻 6. CÓDIGO COMENTADO – HTML, CSS e JS COMPLETOS. Comentários linha a linha (em português!). Código que realmente funciona.
  • ⏱️ 7. DETALHAMENTO MINUTO A MINUTO (50 min) – Tabela com cada minuto da aula. Atividades, descrições, irreverência garantida.
  • ♿ 8. ORIENTAÇÕES PARA ADAPTAÇÕES E INCLUSÃO – Deficiência Visual, Auditiva, Motora, TDAH, TEA, Altas Habilidades. Adaptações práticas e exemplos de código.
  • 📊 9. CRITÉRIOS DE AVALIAÇÃO – Pontuação de 0 a 10. Critérios claros e objetivos.
  • 🔥 10. FRASE DE IMPACTO – Para encerrar a semana com chave de ouro. "O algoritmo não te odeia. Ele só não se importa com você."

// 1. Sintaxe: falta de fechamento de parênteses
// 2. Referência: variável não declarada
// 3. Lógica: o código roda, mas faz a coisa ERRADA
// 4. Runtime: o código quebra durante a execução

// DEBUGGER
function funcaoComDebugger(a, b) {
  debugger; // A execução PAUSA aqui!
  return a + b;
}

🐛 OS 10 ERROS MAIS COMUNS DOS ALUNOS (E COMO CORRIGI-LOS)

# Erro Por que acontece Como corrigir
1 Esquecer de fechar tags HTML Ansiedade, pressa, falta de atenção "Sempre que abrir uma tag, feche imediatamente." Use extensões de auto-fechamento.
2 Confundir = com == e === Acha que tudo é igual no JS "= é atribuição. == é comparação frouxa. === é rigorosa. Use === SEMPRE."
3 Esquecer o ; no final das linhas Python não exige, JS sim "Coloque o ;. É como ponto final na frase."
4 Não usar let ou const Acham que var ainda é válido "Use let para variáveis que mudam, const para as que não mudam."
5 Erro de índice em arrays (começa em 0) Acham que começa em 1 "O primeiro elemento é SEMPRE o índice 0."
6 Não usar console.log() para debug Acham que é "perda de tempo" "console.log() é seu melhor amigo. Use-o. Abuse dele."
7 Não indentar o código Preguiça ou falta de hábito "Indente SEMPRE. Use Shift+Alt+F no VS Code."
8 Usar onclick no HTML em vez de addEventListener Acharam que é mais fácil "onclick no HTML é 2010. addEventListener é o futuro."
9 Não ler as mensagens de erro Acham que é "grego" "A mensagem de erro diz exatamente o que está errado e onde. Leia."
10 Desistir no primeiro erro Frustração, falta de resiliência "Debug é 90% da programação. Persista."
